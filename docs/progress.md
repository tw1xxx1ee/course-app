# Ход работы

## ЛР 1 — Старт проекта на React и TypeScript

Коммит: тег `lab-1`.

Создан проект Vite (React + TypeScript) в папке `frontend`, стартовый экран заменён
собственным экраном «Каталог игр», удалены логотипы и счётчик шаблона.

Проверка:

1. `cd frontend && npm ci && npm run dev` — открывается экран «Каталог игр».
2. Временно присвоить `appTitle` число — `npm run build` падает с ошибкой TS2322.
3. Вернуть строку — `npm run build` проходит.
4. `npm run preview` — показывает готовую сборку.
5. Клонировать репозиторий в новую папку, выполнить `npm ci` и `npm run build` в `frontend`.

## ЛР 2 — Страницы приложения и навигация

Коммит: тег `lab-2`.

Описан тип `Game`, добавлено пять демонстрационных игр, компонент `GameCard`,
страницы списка, карточки, добавления и неизвестного адреса, общий `Layout`
и маршруты React Router.

Проверка:

1. Открыть `/` — показан список из пяти игр.
2. Открыть `/games/g1` и `/games/g2` — разные карточки со всеми полями.
3. Обновить страницу карточки — она открывается напрямую.
4. Открыть «Добавить игру» — видна заглушка и навигация.
5. Открыть `/unknown` — «Страница не найдена».
6. Открыть `/games/missing` — «Игра не найдена».
7. Временно заменить массив на `[]` — «В коллекции пока нет игр.»
8. Проверить «назад»/«вперёд», ширину 360 px и переходы клавишей Tab.

## ЛР 3 — Формы и локальное состояние

Коммит: тег `lab-3`.

Список игр поднят в состояние `App`, добавлены функции создания, изменения и удаления,
переиспользуемая форма `GameForm`, страницы добавления и редактирования, удаление
с подтверждением и фильтр по статусу. Предметное правило: оценка от 1 до 10 либо не указана.

Проверка (в одном сеансе, без обновления страницы):

1. Добавить игру с корректными данными — открывается её карточка, игра есть в списке.
2. Изменить платформу и статус — карточка и список обновились.
3. Внести изменения и нажать «Отмена» — игра не изменилась.
4. Пустое название, пустая платформа, оценка 15 — видна ошибка, поля не очищаются.
5. Переключить фильтр статуса и вернуться к «Все»; выбрать статус без игр — «Показать все игры».
6. Отменить удаление, затем подтвердить. Открыть адрес удалённой игры — «Игра не найдена».
7. Удалить все игры — «В коллекции пока нет игр.», затем добавить новую.
8. Обновить страницу — восстановится демонстрационный набор.

## ЛР 4 — Загрузка справочника по HTTP

Коммит: тег `lab-4`.

Справочник платформ (`frontend/public/demo/platforms.json`) запрашивается через `fetch`
в сервисе `services/platformService.ts` с проверкой `response.ok`, структуры и уникальности id.
Хук `usePlatforms` управляет состояниями loading / error / success и повтором с отменой
устаревшего запроса через `AbortController`. В игре хранится id платформы.

Проверка (DevTools → Network, фильтр `platforms.json`, Disable cache):

1. Открыть «Добавить» — виден GET `/demo/platforms.json`, выбрать платформу и сохранить.
   В редактировании выбрана та же платформа.
2. Slow 3G: во время загрузки «Загружаем платформы…», кнопка «Сохранить» недоступна.
3. Offline перед открытием формы — ошибка; ввести название, вернуть Online, «Повторить» —
   название сохранилось.
4. Временно изменить `platformsUrl` на несуществующий файл — ошибка.
5. Заменить содержимое JSON на `[]` — «Платформ пока нет», затем вернуть и «Повторить».
6. Объект вместо массива, числовой id, отсутствующий name, повторяющийся id — ошибка структуры.
7. Открыть форму на медленной сети и сразу уйти к списку — ошибок на другой странице нет.
8. Вернуть исходный JSON, проверить CRUD, отмену и фильтр ЛР 3.
