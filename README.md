# Каталог игр

Личная коллекция игр и отслеживание прохождения.

- **Автор:** Чумаченко Даня, группа 24ИС
- **Тема:** Каталог игр (вариант 5)

## Основной сценарий

Каталог игр помогает игроку вести личную коллекцию. Пользователь добавляет игру,
указывает платформу, жанр и статус прохождения, ставит оценку и находит
пройденные игры и те, что пока в планах.

## Стек

React, TypeScript, Vite, React Router, Supabase (PostgreSQL, Auth). Node.js 24.19.0 (см. `.node-version`).

## Настройка Supabase

1. В проекте Supabase выполнить в SQL Editor по порядку:
   `supabase/migrations/202610060001_initial_schema.sql`,
   `supabase/migrations/202610130001_games_owner_policies.sql`, затем `supabase/seed.sql`.
2. Скопировать `frontend/.env.example` в `frontend/.env.local` и подставить свои значения:

| Переменная | Что это |
|------------|---------|
| `VITE_SUPABASE_URL` | адрес проекта Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | публичный (publishable) ключ |

Secret key и `service_role` в проекте не используются. Файл `.env.local` в Git не попадает.

3. Authentication → URL Configuration: Site URL `http://localhost:5173`, в Redirect URLs
   добавить `http://localhost:5173/**` (порт — как у запущенного Vite).
4. Вход по email и паролю включён, подтверждение email включено: после регистрации нужно
   перейти по ссылке из письма и затем войти.

## Что работает сейчас

- Регистрация, вход и выход по email и паролю; личные страницы закрыты без входа.
- Игры хранятся в Supabase и сохраняются после перезагрузки; каждый пользователь видит
  и изменяет только свои записи.
- Список игр и карточка игры по адресу.
- Добавление, редактирование (одна общая форма) и удаление игры с подтверждением;
  на время запроса кнопка блокируется, при ошибке черновик остаётся в форме.
- Проверка формы: обязательные название, платформа и жанр; оценка от 1 до 10 или не указана.
- Фильтр по статусу: кнопки с количеством игр, «Все» сбрасывает фильтр.
- Справочник платформ загружается из таблицы `platforms` в Supabase; форма показывает
  загрузку, ошибку, пустой ответ, кнопки «Повторить» и «Обновить справочник»,
  черновик при этом не теряется.
- Общий layout с навигацией, отдельные сообщения для неизвестной страницы и отсутствующей игры.

## Страницы

| Адрес | Страница |
|-------|----------|
| `/auth` | вход и регистрация (открыта без входа) |
| `/` | перенаправление на `/games` |
| `/games` | список игр |
| `/games/:id` | карточка игры |
| `/games/new` | добавление игры |
| `/games/:id/edit` | редактирование игры |
| любой другой | «Страница не найдена» |

Все страницы `/games…` требуют входа: гость перенаправляется на `/auth`.

## Схема данных

| Таблица | Назначение | Ключ | Связь | Доступ |
|---------|------------|------|-------|--------|
| `platforms` | справочник платформ | `id` (text) | — | читают все, изменять из браузера нельзя |
| `games` | личные игры | `id` (uuid) | `platform_id → platforms.id`, `owner_id → auth.users.id` | читает и изменяет только владелец |

Ограничения `games`: название 1–100 символов, жанр 1–50, статус из трёх значений,
оценка от 1 до 10 или пусто.

Модель доступа: `platforms` читают все (и гости); `games` доступна только роли `authenticated`
и только строкам с `owner_id = auth.uid()` — отдельные политики RLS на SELECT, INSERT,
UPDATE и DELETE. Защищённые маршруты в интерфейсе — удобство, границу доступа задаёт база.

## Использование ИИ

ИИ (модели Claude) применялся там, где это было уместно: объяснение незнакомых API,
разбор ошибок, ревью безопасности и рутинная работа. Каждое изменение я проверял сам:
сборкой с проверкой типов, тестами backend, запросами в DevTools → Network и ручным
прохождением сценариев из `docs/progress.md`.

- ЛР 1 — Claude Haiku 4.5: объяснение пути index.html → main.tsx → App.tsx, рутинная очистка шаблона Vite.
- ЛР 2 — Claude Sonnet 5: маршруты React Router (Route, Outlet, useParams) и типизация props; Claude Haiku 4.5: демонстрационные записи.
- ЛР 3 — Claude Sonnet 5: неизменяемое обновление состояния, общая форма создания и редактирования, разбор предметной проверки оценки.
- ЛР 4 — Claude Sonnet 5: проверка response.ok и структуры JSON, отмена устаревшего запроса через AbortController.
- ЛР 5 — Claude Opus 5.5: ревью схемы, ограничений CHECK, GRANT и RLS справочника; Claude Haiku 4.5: seed.sql.
- ЛР 6 — Claude Opus 5.5: политики владельца (USING / WITH CHECK) и план проверки двумя аккаунтами; Claude Sonnet 5: форма входа и состояние сессии.

## Текущие ограничения

Фильтр по статусу пока работает в браузере по уже загруженному списку; поиск и фильтры
в запросе к базе появятся в ЛР 7.
